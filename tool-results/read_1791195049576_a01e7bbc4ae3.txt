     6→## Architecture (agreed foundation — read before working)
     7→
     8→- **Single route app.** The Next.js app exposes ONLY `src/app/page.tsx`. All navigation is client-side hash routing: `#/view-id`, `#/view-id/:param` (e.g. `#/metric/revenue`, `#/insights/ins-sh-1`). No other Next routes may be created.
     9→- Entry: `src/app/page.tsx` (server) → `src/components/app-root.tsx` (client SPA: hash router + layout shell + view registry).
    10→- **Layout groups** resolved in app-root: Public pages (landing/auth) → PublicLayout; onboarding (screens 11–20) → OnboardingLayout; `admin/*` → AdminShell; `state/404`, `state/session-expired`, `prototype-index` → bare; everything else → AppShell (sidebar + header).
    11→- **State**: Zustand store `src/lib/store.ts` (current business, date range, notifications, actions/experiments/goals mutations, connections, settings). Toasts via `sonner` (`toast.success(...)` etc.).
    12→- **Data**: coherent shared datasets in `src/lib/data/*` — SwiftHaul Logistics (service, Sep 2026 vs Aug 2026) and KoraHome Store (ecommerce, Shopify). All screens MUST use these numbers (consistency requirement #46).
    13→- **Design system**: Tailwind + shadcn/ui. Semantic colors: blue-600 = data/primary actions, violet-600 = AI/intelligence, emerald-500 = positive, amber-500 = attention/opportunity, red-500 = risk. 70–80% neutral slate. Provenance badges everywhere (Measured / User supplied / Estimated / AI interpretation). Confidence language High/Medium/Low. No dead primary buttons (navigate, open dialog, or toast).
    14→- **View registry**: each screen group owns a directory `src/components/screens/<group>/` with an `index.tsx` exporting a `ViewMap` (`Record<string, ScreenComponent>`). `src/components/screens/registry.ts` holds all 114 screen metadata for the Prototype Map.
